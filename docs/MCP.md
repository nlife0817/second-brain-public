# MCP: работа с трекером из Claude

Трекер отдаёт свои задачи наружу по протоколу MCP — `POST https://brain.example.com/api/mcp`.
Агент видит проекты и задачи, читает описания и вложения, комментирует и меняет
настройки — ровно в тех пределах, в которых это может человек, чьим токеном он
подключён.

Внутреннее устройство и правила, которые легко нарушить правкой, — в
[src/lib/core/CLAUDE.md](../src/lib/core/CLAUDE.md), раздел «Внешние агенты».

## Подключение

1. Настройки организации → «Интеграции: токены доступа».
2. Задайте имя (по нему потом искать, чей это ключ) и режим:
   - **Только чтение** — агент видит задачи и файлы, но ничего не меняет;
   - **Чтение и изменение** — работает вашими правами целиком.
3. Нажмите «Выпустить». Значение показывается **один раз** — в базе лежит только
   его хеш. Забыли — выпускайте новый.
4. Скопируйте готовую команду прямо из этого блока:

```bash
claude mcp add --transport http second-brain https://brain.example.com/api/mcp --header "Authorization: Bearer <токен>"
```

Проверить подключение можно вопросом «что ты видишь в трекере» — агент вызовет
`whoami` и назовёт организацию и роль.

## Что видно в трекере

Каждое действие агента пишется в историю задачи и в журнал организации с
пометкой **«через Claude»** — рядом с именем владельца токена. Комментарии
помечены так же. Уведомления, подписки и push работают как обычно: команда
узнаёт о правке ровно так же, как узнала бы о вашей.

## Инструменты

**Чтение**

| Инструмент | Что делает |
|---|---|
| `whoami` | Организация, роль, режим токена |
| `list_projects` | Проекты и доступ к ним |
| `list_tasks` | Задачи: все, проекта, свои, подзадачи; с отбором по названию, исполнителю и статусу |
| `get_task` | Карточка целиком: описание Markdown'ом, комментарии, лента, подзадачи, связи, вложения |
| `get_attachment` | Файл по id: картинка приходит изображением, текстовые форматы — текстом |
| `search` | Сквозной поиск по задачам, проектам и клиентам |
| `get_org_settings` | Статусы, метки, поля, типы связей, участники — источник id для правок |

**Правка задач**

`create_task`, `update_task` (в том числе `archive: true`), `add_comment`,
`delete_comment`, `follow_task`, `link_task`, `delete_task`.

**Настройки**

`manage_project`, `manage_project_members`, `manage_statuses`, `manage_tags`,
`manage_fields`.

## Описание задачи

Описание — документ (таблицы, колонки, картинки с подписями, якоря обсуждений),
поэтому читается и пишется оно по-разному:

- **читается** Markdown'ом; картинки и файлы видны как `![подпись](attachment:<id>)`
  — по этому id их забирает `get_attachment`;
- **пишется** HTML — тем же, каким его хранит редактор. Чтобы поправить описание
  точечно, агент берёт исходник (`get_task` с `include_html`) и возвращает
  правленый документ целиком.

Markdown в обе стороны не поддерживается намеренно: он не умеет выразить колонки,
подписи и привязку обсуждений к тексту, и правка описания стирала бы их.

## Безопасность

- Токен даёт **ровно те права, что есть у его владельца** — не больше. Закрытый
  проект, недоступный человеку, недоступен и агенту.
- Исключение владельца из организации закрывает токен само собой.
- Отозвать токен можно в том же разделе настроек; администратор организации
  видит и отзывает чужие токены.
- Утёкший токен = доступ к тем же данным, что и украденная сессия. Значение
  хранится только у вас; в базе — хеш.
- Дата последнего использования в списке отвечает на вопрос «этим ключом ещё
  пользуются?».
