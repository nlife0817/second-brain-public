# Second Brain — командный трекер задач

Мультитенантное веб-приложение: организации, проекты, задачи в четырёх видах,
база знаний с таблицами и формулами, CRM-контур, уведомления в push и телеграм,
мобильная PWA. Работает на своём сервере, выкатывается по push в ветку.

Next.js 16 (App Router) · React 19 · TypeScript · Postgres напрямую, без ORM ·
Tailwind v4 + Base UI · Docker Compose на VPS

> **Публичная копия репозитория.** Что именно вырезано — в разделе
> [«О публичной копии»](#о-публичной-копии) в конце.

## Что это

Трекер, выросший из личного «второго мозга» в командный инструмент. Ядро
мультитенантное: организация → проекты → задачи, роли участников и гостевой
доступ, единый слой правил доступа. Первая, персональная версия удалена из кода
целиком — в истории коммитов её снос виден как отдельный этап.

## Возможности

**Задачи.** Подзадачи любой вложенности, связи между задачами, свои поля, метки,
статусы наборами (у проекта-разработки свой набор, у остальных — общий),
повторяющиеся правила, учёт времени. Три даты вместо одной: дедлайн, начало
на диаграмме Ганта и «дата работы» — когда человек собирается этим заняться.

**Четыре вида одного списка.** Таблица с группировкой и массовыми операциями,
доска с перетаскиванием, диаграмма Ганта (стрелки зависимостей, перетаскивание
и растягивание полос, три масштаба), календарь. Модели видов — чистые функции в
`src/lib/core/` (`views.ts`, `gantt.ts`, `calendar.ts`); компоненты только
рисуют и потому легко тестируются.

**Спринты и бэклог.** Для проектов в режиме «Разработка»: бэклог, наборы
статусов, планирование по часам, ёмкость спринта, перенос с осмысленным
поведением сроков.

**Описание задачи — полноценный документ.** Редактор на Tiptap: таблицы,
колонки, картинки с подписью, вложения, якоря комментариев прямо в тексте,
полноэкранный режим с обсуждением сбоку.

**База знаний.** Папки и документы, а в них — таблицы с собственным движком:
96 функций в формулах, протягивание за уголок, меню по правой кнопке, границы
ячеек, свои форматы чисел, вкладки листов, свой буфер обмена. Импорт `docx`,
`xlsx`, `csv` и выгрузка обратно. Разбор форматов и модель книги — чистое ядро
в [`src/lib/core/sheet/`](src/lib/core/sheet/), 5000 строк без единого обращения
к DOM.

**CRM.** Сделко-центричная модель: воронки, стадии с историей переходов,
формы захвата заявок с разметкой UTM.

**Уведомления.** Один диспетчер на два канала: web-push через Service Worker и
телеграм-бот (Bot API напрямую, без зависимостей). Настройки — по типам событий
и по каналам отдельно.

**Внешние календари.** Google Calendar по OAuth и подписки ICS. Refresh-токены и
приватные ссылки шифруются отдельным ключом: содержимое базы уезжает в ночной
дамп, а такой токен даёт бессрочный доступ к чужому календарю.

**Внешние агенты.** Свой MCP-сервер на `/api/mcp`: агент подключается по токену
и работает ровно в правах человека, чьим токеном подключён. Каждое его действие
попадает в историю задачи с пометкой «через Claude» — команда видит правку так
же, как видела бы человеческую. Инструменты — [docs/MCP.md](docs/MCP.md).

**Мобильная оболочка.** Отдельная PWA на `/v2/m/*` с нижним таб-баром; `proxy.ts`
уводит туда мобильные user-agent'ы, `?desktop` возвращает обратно.

## Что интересно посмотреть в коде

| Решение | Где |
|---|---|
| **Единственный источник правил доступа.** Все проверки прав живут в одном модуле; роуты не пишут SQL и не решают, кому что видно | [`src/lib/core/policy.ts`](src/lib/core/policy.ts), [`context.ts`](src/lib/core/context.ts) |
| **Postgres без ORM.** Тонкая обёртка над `postgres.js`; `prepare()` конвертит `?` в `$N`, чтобы запросы читались как SQL | [`src/lib/sql.ts`](src/lib/sql.ts) |
| **Свой движок таблиц.** Разбор формул, зависимости ячеек, ряды протягивания, форматы, чтение и запись xlsx — отдельно от React | [`src/lib/core/sheet/`](src/lib/core/sheet/) |
| **Ноль клиентских запросов на холодной загрузке.** Экраны переведены на серверный рендер: было девять запросов из браузера, стало ни одного | [`src/app/v2/`](src/app/v2/) |
| **Своя аутентификация.** scrypt из `node:crypto`, сессия — cookie, подписанная HMAC-SHA256 через WebCrypto (работает в Edge-рантайме), ограничение попыток входа | [`src/lib/auth/`](src/lib/auth/) |
| **Выкат с откатом.** Миграции применяются по одной, каждая в своей транзакции, с учётом в таблице; при провале healthcheck сервер возвращается на предыдущий образ | [`deploy/`](deploy/), [docs/DEPLOY.md](docs/DEPLOY.md) |
| **Правила, записанные до кода.** 684 строки конвенций ядра: что нарушать нельзя и на какие грабли уже наступали | [`src/lib/core/CLAUDE.md`](src/lib/core/CLAUDE.md) |

## Карта репозитория

| Путь | Что там |
|---|---|
| `src/app/v2/**` | Десктопные экраны: сводка, проекты, задачи, база знаний, CRM, время, настройки |
| `src/app/v2/m/**` | Мобильная PWA |
| `src/app/api/v2/**` | REST API — тонкие роуты: zod → проверка прав → сервис ядра |
| `src/app/api/mcp/` | Вход внешних агентов по протоколу MCP |
| `src/lib/core/**` | Доменный слой: сервисы, чистые модели видов, правила доступа |
| `src/lib/auth/**` | Пароли, подпись сессии, троттлинг входа |
| `src/components/v2/sheet/` | Полотно таблиц: виртуализация, жесты, строка формул |
| `src/components/v2/editor/` | Расширения Tiptap для описания задачи |
| `supabase/migrations/` | 64 SQL-миграции (каталог сохранил историческое имя, Supabase больше не используется) |
| `deploy/` | docker-compose, Caddy, контейнер расписаний, скрипты выката и бэкапа |
| `design/prototypes/` | Кликабельные HTML-прототипы экранов — открываются без базы |

## Локальный запуск

```bash
npm install
npm run dev
```

Откроется `http://localhost:3000` и уведёт на `/v2/my`. Нужен `.env.local` с
`DATABASE_URL` и `SESSION_SECRET`. Вход можно не поднимать: задайте
`DEV_USER_EMAIL`, и проверка сессии выключится — только при
`NODE_ENV !== "production"`. Полный список переменных с объяснением, зачем
каждая, — в [deploy/env.example](deploy/env.example).

```bash
npm run build
npm run lint
npm run test
```

Прототипы экранов открываются без сборки и без базы — достаточно открыть
`design/prototypes/index.html` в браузере.

## Продакшн

Собственный VPS, Docker Compose: Next.js в standalone-сборке, Postgres, Caddy с
автоматическим Let's Encrypt и контейнер расписаний вместо `pg_cron`. Push в
продакшн-ветку запускает GitHub Actions: тесты и сборка на раннере, затем по SSH
пересборка образа на сервере, применение миграций, healthcheck и возврат на
предыдущий образ при неудаче.

- Автодеплой, разовая настройка и откат — [docs/DEPLOY.md](docs/DEPLOY.md)
- Первичное развёртывание и грабли — [docs/VPS-MIGRATION.md](docs/VPS-MIGRATION.md)

## О публичной копии

Это очищенный срез приватного репозитория, собранный для показа. История
коммитов сохранена целиком и переписана: перечисленное ниже убрано не только из
текущего состояния, но из всех ревизий.

**Убрано:** рабочие заметки агента (`.claude/`), конфигурация MCP-клиента
(`.mcp.json`), внутренний отчёт об аудите мёртвого кода.

**Заменено на плейсхолдеры:** домен продакшна, IP сервера, личные адреса почты.

**Секретов в репозитории не было и нет.** Файлы `.env*` никогда не отслеживались
git, в [deploy/env.example](deploy/env.example) лежат только пустые заготовки с
объяснением, что в каждую подставить, а CI берёт ключи из GitHub Secrets. Это
проверено сканированием всей истории, а не только текущего состояния.

Проект разрабатывался вместе с Claude Code — отсюда `CLAUDE.md` в корне и в
`src/lib/core/`, а также трейлеры `Co-Authored-By` в коммитах. Файлы оставлены
намеренно: это рабочая архитектурная документация, а не служебный мусор.
